# colorful-mgmt 项目记忆索引

本目录保存当前项目的背景、实现约定、架构与业务决策、用户确认事项和环境位置。它不是只放环境，也不是低优先级的备忘录：已确认决策具有约束力，发现与源码冲突时核对并说明，不能静默废止。

## 按主题读取

| 触发主题 | 记忆文件 |
|---|---|
| 修改本项目代码、分层、模型、命名、分页、接口错误或登录 | [跨模块项目约定](project-conventions.md)；模型目录标准见 [通用模型归属](../rules/engineering.md#模型归属)，本文件只路由项目落实情况 |
| 诊断方案、任务、结果、报告、页面或对应表 | [诊断模块](modules/diagnosis.md) |
| 提示词模板、管理页或发给模型的提示词 | [提示词管理](modules/prompt-template.md) |
| 大模型渠道、策略、协议、联网或引用 | [大模型调用](modules/llm.md) |
| 浏览器自动化、平台登录/发文中的人工处理、接管界面 | [人工接管](modules/browser-takeover.md) |
| 本项目文档落盘、迁移脚本、数据库/前端安全审查 | [工程实践与产出位置](project-practices.md) |
| 编译、真实回归、查库、部署或定位运行工具 | [环境线索](runtime-env.md) |

## 维护边界

可复用的类/方法注释、命名、测试和可靠性要求维护在 rules，通用执行步骤放 workflows；项目特定的目录、表、字段、接口、资源名和选型原因放本目录。示例用到某项目名称不等于业务事实，示例必须明确仅演示格式。

按入口授权维护记忆，新增主题先检查能否并入已有文件。临时进度、测试结果和待处理事项写交接或当前验收文档。运行快照可能失效，使用前核对；决策更新须有用户确认或明确依据，不能把记忆迁移当成改变决策。
