# colorful-mgmt 工程实践与产出位置

本文件记录本项目具体使用的框架、路径和工程产出方式；开发方法和通用质量要求仍维护在 rules。

## 数据库迁移

- 新表或变更表结构同时核对 Entity、DAO、`src/main/resources/db/mysql/001_init.sql`；已有库提供保留数据、先检查且可重复执行的迁移脚本与执行顺序，不创建空表替代旧数据。
- 迁移与服务器执行步骤放 `.doc/<分支>/`，先改库还是先发代码按本次兼容边界说明。

## 数据库与前端安全

- MyBatis-Plus 不拼接外部输入；`last()` 分页只用 PageQuery 生成的片段。
- 管理页面展示模型和内容平台的外部文本时防 XSS；Fastjson 不开 autoType。
- 威胁建模核对后台账号会话、模型密钥、平台登录态与项目数据资产。

## 文档与验收产出

- 文档落在 `.doc/<分支>/<需求简写>-详细设计.md` 等已有目录；详细设计持续更新同一文件，不追加时间戳副本。历史交接是快照，当前任务只更新相关结论，不批量改写历史记录。
- 标题用“【模块】需求标题 - 详细设计”，有需求编号放最前。写新设计前参考 [诊断地域报告详细设计](../../.doc/20261115_area_diagnosis/诊断地域报告-详细设计.md) 或 [人工接管详细设计](../../.doc/20261029_login_use_config/浏览器人工接管框架-详细设计.md)，只参考组织方式，不复制历史实现结论。
- 重要任务在 [HANDOFF](../../.doc/HANDOFF.md) 记录结果、验证、风险、运行实例状态和下一步；逐方法审计多时写当前验收文档并从交接引用，不放长期记忆。
- 接口回归脚本及报告放 `.test/`；报告保存 `.test/<分支>/<分支>_<实际年月日时分秒>-测试报告.md`，文件名中的分支斜线转换为安全短名。报告按通用运行回归要求区分真实请求、测试替身与当前运行实例。
