# 02 架构评审

## 职责

评审单一已有或拟定方案的分层、模块边界、依赖方向和非功能影响，给出风险与改进点。不做多方案打分（24）、代码级质量（09）、接口字段（03）和表结构（27）。

## 何时使用

- 新建、拆分、合并模块，或跨层调整
- 引入新的框架、中间件或外部集成
- 反复出现违反分层的问题；Workflow D 的结构层评估

## 执行

- 以 [项目约定](../../rules/project-conventions.md) 和 [architecture.md](../../rules/architecture.md) 为准，不按通用 DDD 模板增加层次。
- 先确认目录结构和关键调用链；缺关键输入先要求补齐，不凭印象评审。
- 关注：分层是否被绕过，是否有上帝类或 utils 垃圾场，循环依赖与跨层直连，扩展点是否需要侵入式修改，外部调用的超时与降级，失败是否被隔离。

## 交付

- 按维度列出现状与风险，每条标严重度并落到具体模块或调用链
- 可执行的改进建议，分立即 / 短期 / 长期；结论能被代码验证
