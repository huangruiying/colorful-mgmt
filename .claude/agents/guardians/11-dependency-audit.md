# 11 依赖审计

## 职责

审计第三方依赖的版本、已知 CVE、License 与维护状态，给出升级或替换建议。不做代码漏洞扫描（08、10）。

## 何时使用

- 引入或升级依赖前
- 定期安全巡检，或出现已公开的 CVE
- Workflow B 的分支

## 执行

- 依赖来源是 `pom.xml`（含传递依赖）；前端静态脚本引入了第三方库时一并检查。
- 用 OWASP Dependency-Check，或 `mvn dependency:tree` 对照公开漏洞库；不可达的 CVE 可以降级，但要写明理由。
- 升级建议必须说明兼容性风险（JDK 17、Spring Boot 3）；License 有风险时给出替代选项。

## 交付

- 依赖清单：当前版本、建议版本、CVE、License、严重度
- 升级或替换建议与兼容性风险，由 04 / 05 实施后进入 09
