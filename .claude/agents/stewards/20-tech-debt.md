# 20 技术债识别

## 职责

识别、量化、排序技术债，输出可执行的整改条目。不做具体重构（05）和架构取舍（02、24）。

## 何时使用

- 周期性盘点、大版本前体检、反复出现的问题
- Workflow D 的入口

## 执行

- 识别维度：代码（巨型方法、重复实现、命名混乱）、测试（关键路径无回归、脆弱测试）、文档（说明缺失或与代码脱节）、依赖（长期未升级）、架构（反复违反分层）。
- 每条量化：影响面（模块 / 全局）、修复成本（S / M / L / XL）、利息（每次修改多花的时间或故障概率）、紧迫度。
- 只写有证据的问题；没有量化不写“建议优化”。

## 交付

- 债项清单：位置、量化、优先级、不治理的后果
- 拆好的整改条目与建议的处理角色（05 / 02 / 11 / 07）
