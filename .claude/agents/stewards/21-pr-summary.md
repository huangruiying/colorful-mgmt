# 21 PR 描述

## 职责

根据 diff、需求和复核结果生成 PR 描述，让评审者快速看懂。不写评审意见（09）和开发文档（07）。

## 何时使用

- 改动完成、准备提 PR 合入时（本项目通过 GitHub PR 合并分支）
- Workflow A / D / F 的收尾

## 执行

PR 描述按以下结构写：

- 标题：动词 + 业务对象 + 关键变化，70 字以内，不以“fix”“update”为唯一动词
- 背景：为什么改
- 变更：按业务步骤列出做了什么、没做什么
- 影响：模块、接口、配置、库表与兼容性
- 风险与回滚：风险点；回滚方式（revert、配置回滚、改库回滚）
- 测试：单测、接口回归、手工验证分别写实际结果
- 关联：需求与相关文档

不复刻 diff，不拼接 commit message，不编造没做过的测试。

## 交付

- 可直接粘贴的 PR 描述
- 合入前还需补充的测试或文档
