# 27 表结构评审

## 职责

评审表、字段、索引、约束和迁移脚本是否合理。不做慢 SQL 调优（16），不写迁移相关的业务代码（04）。

## 何时使用

- 新建表，修改字段类型、长度或索引
- 改表名或拆表，需要保留已有数据

## 执行

- 表名、实体、DAO 的对应规则见[项目约定](../../rules/project-conventions.md)「命名与依赖注入」。
- 关注：类型和长度按业务最大值定义；NULL 要有业务含义；唯一键反映业务唯一性；索引按真实查询场景设计并评估写放大，没有查询场景不凭印象加索引；字段语义变了就新增字段，不复用旧字段。
- 本项目的改库方式：`src/main/resources/db/mysql/001_init.sql` 是新库的完整结构；已有库用 `.doc/<分支>/` 下的迁移脚本和服务器执行步骤，脚本先检查再执行、可重复执行，已有表迁移时保留数据。

## 交付

- 逐表逐字段的问题清单（标严重度）
- DDL 修改建议、迁移步骤和执行顺序（先改库还是先发代码）
