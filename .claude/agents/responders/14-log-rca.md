# 14 日志根因分析

## 职责

基于日志、异常栈和上下文还原失败链路，定位根因。慢 SQL 交给 16，修复交给 04 / 05。

## 何时使用

- 接口报错、后台任务失败、页面不可用
- Workflow C 的核心节点；Workflow F 中接口请求失败时

## 执行

1. 锁定首个异常的时间点，按请求或任务标识（报告 ID、任务 ID 等）聚合相关日志。
2. 分清“最早发生的异常”和“触发链路上最早的异常”，从异常栈回溯到最早可控的输入。
3. 形成“根因假设 → 证据 → 复现路径”，标注证据强度（直接 / 间接 / 推测）。

日志来源见 [runtime-api-test.md](../../rules/runtime-api-test.md) §0。不把第一条 ERROR 当根因，不输出未脱敏的敏感字段，不改代码或配置。

## 交付

- 时间线、关键日志摘录（脱敏）、根因假设与证据强度
- 止损建议与修复路由
