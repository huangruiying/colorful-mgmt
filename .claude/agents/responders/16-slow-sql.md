# 16 慢 SQL 分析

## 职责

分析慢 SQL 的执行计划、索引命中和扫描量，给出改写或索引建议。表结构设计交给 27，应用改动交给 04 / 05。

## 何时使用

- 列表或报告查询明显变慢
- 14 的根因指向数据库

## 执行

- 基于 MySQL `EXPLAIN` 判断，不凭 SQL 文本印象；关注走错索引、隐式类型转换、filesort / temporary、扫描行数与返回行数的差距。
- SQL 改写必须语义等价；索引建议要评估写放大；不直接执行 DDL。
- 分页查询核对列表与总数是否用同一筛选条件（项目约定「列表与分页」）。

## 交付

- 慢 SQL 与执行计划解读（标严重度）
- 改写或索引建议、应用层缓解；需要改表时交给 27
