# 调查与审查

本文件合并故障、性能、数据库、安全和依赖审查的独有检查项。结论附具体文件、行号、请求/任务标识或脱敏日志，事实与假设分开；需要改代码时回 [公共交付流程](code-change-flow.md)。

## 故障与性能

1. 保存发生时间、环境、目标标识、错误原文和当前状态，不先改配置覆盖现场。
2. 按同一请求或任务聚合日志与异常栈，区分第一条 ERROR、最早异常和真正触发点；对照当前源码、运行版本、数据库状态与已知正常样例。
3. 给出假设 → 直接/间接证据 → 复现/反证。能缓解不代表已经证明根因，不把网络 EOF 直接等同某种协议故障。
4. 慢 SQL 获取 MySQL EXPLAIN、扫描/返回行数和索引；查隐式转换、filesort、temporary、筛选与分页总数口径，索引评估写放大。不凭 SQL 外观加索引。
5. 应用慢点先取 JFR、线程栈、剖析或耗时数据，区分 CPU、分配、锁、线程池及外部阻塞；无数据先设计测量，不臆测收益。

只读排查先行，修数据须在授权内比较前后、备份、最小事务修改并回查；重启只操作已确认归属的目标进程，部署按实际执行手册。

## 安全与依赖

| 触发 | 检查与证据 |
|---|---|
| 新输入、页面、上传、外部 URL | 追踪输入到 SQL、命令、模板、DOM、文件或网络的完整 Source → Sink；检查参数化、转义、路径与地址白名单 |
| 动态 SQL | MyBatis-Plus 不拼接外部输入；last 分页只用 PageQuery 生成的片段 |
| 外部文本 | 模型、平台返回内容展示防 XSS；Fastjson 不开 autoType |
| 鉴权、密钥、会话 | 画信任边界与数据流，按 STRIDE 检查资产、威胁、缓解与残余风险，核对现有安全配置 |
| 新增/升级依赖 | 从 pom 与传递依赖、实际前端引入取版本，对官方公告/漏洞库核查 CVE、许可证与兼容风险；不凭旧记忆写“安全” |
| 新表/字段/索引 | 类型长度、NULL 语义、唯一性、真实查询、迁移数据保留与发布顺序 |

有可用工具时用 Semgrep、SpotBugs/FindSecBugs、Dependency-Check 等补证据；不可用明确说明人工检查范围，不虚构扫描报告。风险按严重度、可触达条件、影响和修复建议列出，严重问题先报告但继续必要取证，不静默停止全部工作。

## 架构、取舍与技债

先查目录、真实调用链、数据对象及资源生命周期，按项目工程边界评估；多个方案对比一致性、复杂度、性能、成本、风险和回滚。推荐需写代价，未知收益标明待验证。

债项落到具体位置、重复问题或维护成本，给优先级与不处理的后果；不凭“看着复杂”进行无范围重构。审查任务只交发现和建议，实施需在用户授权范围内。
