# 多场景路由细则

只在任务存在多个可能的执行目标、需要追加风险专题或自定义流程时加载；普通任务直接按 [CLAUDE.md](../CLAUDE.md) §3 执行。

## 选主流程

- 按用户目标选择主流程，不按关键词数量让用户选 Agent。
- 用户已指定或已确认方案时复用，不重复确认同一范围。
- 需求模糊、只有目标没有路径时，先按 01 拆解和澄清，再进入实现。
- 多场景有关联时，在主流程中按需追加专题阶段；例如实现后补相关测试，不另起全量联调流程。
- 只有不同方案会改变产品流程、架构边界、外部副作用或工作范围时，说明具体取舍并澄清。
- 多个 Agent 命中同一阶段时，按职责边界取最贴近的一个，其余只作为检查视角，不同时展开多份结论。

## 风险升级

各流程命中下列情况时追加对应角色：

| 情况 | 追加 |
|---|---|
| 新增或修改用户输入入口（接口参数、页面表单、上传、外部回调） | 10 |
| 涉及鉴权、密钥或敏感数据 | 26 + 08 |
| 新增或升级依赖 | 11 |
| 新建表或修改表结构、索引 | 27 |
| 改动接口语义或字段 | 03 |
| 故障根因指向数据库 | 16 |
| 改写已上线行为，或需要在多个方案中定取舍 | 24；结论经用户确认后写入项目约定或对应模块文件 |

## 执行约束

- 角色文件按当前阶段逐个读取，不能因跨组就一次加载全部目录。
- 自定义流程只列当前任务必要步骤与验收，不展示无关候选角色。
- 执行方法由 code-change-flow 或相应专题 Workflow 规定；不在此复刻规则。
