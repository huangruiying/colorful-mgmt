# Python 注释硬性规则

适用于 Python 代码以及测试、回归与维护脚本。以下强制要求不能因规则精简、脚本短或“名称已清楚”而弱化；不追溯批量修改本次未涉及的旧代码。

## 文件与类

- 文件头部注释必须说明模块职责、核心流程和不负责的边界。
- 类注释必须说明核心抽象、使用场景、生命周期或边界。
- 注释用中文表达目的和规则，不逐行翻译语法。示例只演示格式，不表示项目存在同名接口或类。

## 方法说明

有参数或有返回值的方法，必须写完整四段：功能 / 作用 / 参数 / 返回。参数名后对齐描述列；返回段列清不同结果及含义，不能仅一句笼统描述。

禁止用单行 docstring 代替四段，有入参不能省参数段，有返回不能省返回段。无返回值时返回段明确写“无”，不编造返回值。

例外：无参数、无返回值、且名称已完全自解释的极简私有函数，可省略。

```python
def collect_failed_results(results):
    """
    功能:
        筛选失败的回归结果。
    作用:
        供报告列出需要重新验证的接口，不发请求、不修改结果。
    参数:
        results:    本轮回归结果列表
    返回:
        非空列表:   本轮失败的结果
        空列表:     本轮没有失败结果；不代表未测试接口已通过
    """
    # 只筛选已明确失败的结果，不把未测试结果归入成功
    return [result for result in results if result["status"] == "FAILED"]
```

## 主流程阶段

对外主流程、编排、批处理方法包含三个及以上连续业务阶段时，必须使用编号注释，方法 docstring 不能代替步骤注释。

- 普通流程用 `# 1. xxx`。
- 生命周期、并发与收尾可用 `# ===== 1. xxx =====`。
- 同一方法只用一种编号格式；不使用“处理数据”“执行逻辑”等泛化说明，不每行都加注释。
- 读取数据、调用外部服务、转换、落库或返回具有不同目的与顺序时按实际业务阶段划分，不按行数或函数名判断。

```python
# 1. 读取待验证的接口与预期结果
# 2. 逐个请求并记录响应，失败保留证据
# 3. 汇总通过、失败与未测试接口，生成回归报告
```

## 生命周期与收尾

说明资源所有权、执行顺序和原因，尤其是监听解绑、在途任务等待与资源释放，不能只写“清理资源”。

```python
# ===== 1. 解除监听，避免关闭期间继续进入新响应 =====
# ===== 2. 等待已进入的处理完成，避免响应读取被中断 =====
# ===== 3. 释放本次拥有的资源，不关闭共享资源 =====
```

## 关键片段与兼容

下列片段必须在代码块前说明按什么规则筛选、转换或收集：

- 带业务过滤条件的列表推导、集合推导。
- 从批量数据拆出已存在、待新增、待处理、失败项。
- 幂等、防重复、兼容历史数据的过滤。
- 字段转换、归一化、序列化与反序列化。

兼容旧数据、历史字段、默认兜底的分支必须说明存在原因；不得给未证实的缺失字段补“合理默认值”。只写“遍历数据”“返回结果”等翻译式注释不合格。

## 同步与审计

修改的方法检查完整正文，改动职责与行为时同步注释；按 [公共交付流程](../../workflows/code-change-flow.md) 记录适用性。文件、类、方法四段、阶段编号、关键片段、兼容和生命周期逐项核对，不用编译或脚本测试替代注释审计。
