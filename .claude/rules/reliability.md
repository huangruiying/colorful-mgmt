# 异常、日志与外部调用

## 失败边界

异常与 HTTP 状态映射唯一维护在 [项目约定「接口异常响应」](../memory/project-conventions.md)。具体异常类型和响应结构属于项目选择；系统故障不能伪装成参数错误或空数据。

- 优先捕获具体异常类型，只有确实需要兜底才用 Exception。校验直接抛明确异常；catch 转换时保留 cause，消息写业务原因，不拼接下层异常消息泄漏细节。
- 只在能恢复、转换为业务状态或对外响应的边界 catch；兜底 catch 放在全局接口边界或后台执行器单轮边界，防止一个任务异常终止整个轮询。
- 影响主产物、正确性或状态的核心操作失败必须可见；方法返回 null、false 或空集合只能表示契约约定的正常结果。
- 进度显示、辅助诊断和非必要通知失败由对应辅助方法内部 try-catch 隔离、记 warn，不阻断主产物。资源释放不是一律可忽略的辅助动作：按资源所有权收尾，避免清理异常覆盖原异常。
- 重试只适用于可恢复的瞬时错误，设置次数、间隔和幂等边界；参数非法、格式错误、明确拒绝不自动重试。模块明确禁止自动重试时以模块决策为准。
- 降级必须说明触发条件、结果损失与用户可见状态，不能返回看似成功的假结果。

DAO 和外部客户端保留原始失败事实，不把存储或调用异常伪装成空数据；Controller 不写查询、过滤、插入等业务编排，Business/Service 不用 null 代替失败，不散落重复查重逻辑。

## 日志

谁真正处理异常谁记录，同一异常不层层重复打印。记录业务动作、对象 ID、阶段、实际渠道、必要状态与耗时，字段名稳定便于检索；有请求标识时关联请求标识，系统故障保留堆栈。

| 级别 | 使用场景 |
|---|---|
| error | 核心操作失败、未预期系统故障 |
| warn | 可继续的异常、重试、降级、输入或业务拒绝 |
| info | 关键状态迁移、业务完成、必要外部调用结果 |
| debug | 受控调试细节 |

必须记录异常捕获边界、关键业务完成与状态迁移，能定位后台任务起止、外部调用失败和恢复、重试触发与结束、降级；不能只记录成功而遗漏失败。避免入口与下层重复记录同一调用；不逐条打印高频循环、轮询心跳、整个对象或整包报文。禁止打印隐私信息和未脱敏个人标识；凭据与原文保护统一遵守项目入口及项目约定。DEBUG 不依赖线上长期保留，不把“进入方法”“开始循环”等日志当注释。

## 外部调用

使用现有客户端、连接池和超时配置。确认请求契约、公共响应、业务状态、必填字段与未知状态；调用成功不等于业务成功，HTTP 200 也不自动代表输出有效。

数据规模、输出限制、失败语义与实测来源按 [注释规范](comments/comment-java.md) 说明。供应商行为与参数查实际协议或官方资料，测试替身只能验证内部逻辑。
