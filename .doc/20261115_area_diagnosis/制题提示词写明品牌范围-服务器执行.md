# 制题提示词写明品牌范围 - 服务器执行步骤

给两个制题提示词（生成母题、按地域改写问题）各新增一版，写明品牌认知题必须直接询问本项目、竞品比较题必须是本项目与竞品比较，再发新代码。只往 `geo_prompt_template` 新增行，不改表结构、不动已有的行，不用停服务。SQL 即同目录 [制题提示词写明品牌范围.sql](制题提示词写明品牌范围.sql)，可重复执行。

新代码多了一条校验：品牌认知题、竞品比较题的问题里必须出现项目名称或别名。它用在生成候选、按地域改写、保存方案和发起诊断任务四处，所以**已有方案里不符合的题，发新代码后保存方案和发起任务都会被拦**，提示里会列出题号。第 1 步先把这些方案查出来。

顺序：第 1 步查方案（只读）→ 第 2 步改库 → 第 3 步发新代码。改库和发代码谁先谁后都不会坏数据：只发了代码、提示词还是旧的，生成候选更容易整批失败；只改了库、代码还是旧的，没有影响。

服务器目录按 `deploy/upload-code-to-server.sh` 的 `REMOTE_DIR`（`/root/colorful-geo-mgmt`）书写。本机库的执行情况见文末。

## 1. 服务器：查出需要先改题的方案（只读，整段粘贴执行）

```bash
cd /root/colorful-geo-mgmt/deploy && docker compose -f docker-compose.yaml --env-file .env exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot --default-character-set=utf8mb4 --table colorful_geo' <<'SQL'
-- 品牌认知题（BRAND）、竞品比较题（COMPARISON）里，问题原文没有出现项目名称或别名的题；序号与方案页问题列表的序号一致
SELECT q.plan_id AS 方案, p.name AS 方案名, q.brand_scope AS 品牌范围, COUNT(*) AS 题数,
       GROUP_CONCAT(q.sort_order + 1 ORDER BY q.sort_order SEPARATOR '、') AS 序号
FROM geo_diagnosis_plan_question q
JOIN geo_diagnosis_plan p ON p.id = q.plan_id
JOIN geo_project_info i ON i.id = p.project_id
WHERE q.brand_scope <> 'NON_BRAND'
  AND INSTR(LOWER(REPLACE(q.question_text, ' ', '')), LOWER(REPLACE(i.name, ' ', ''))) = 0
  AND NOT EXISTS (
      SELECT 1 FROM JSON_TABLE(COALESCE(i.aliases, JSON_ARRAY()), '$[*]' COLUMNS (alias VARCHAR(200) PATH '$')) a
      WHERE TRIM(COALESCE(a.alias, '')) <> ''
        AND INSTR(LOWER(REPLACE(q.question_text, ' ', '')), LOWER(REPLACE(a.alias, ' ', ''))) > 0)
GROUP BY q.plan_id, p.name, q.brand_scope
ORDER BY q.plan_id, q.brand_scope;
SQL
```

没有输出表示没有受影响的方案。有输出时，发新代码后这些方案要先在方案页把列出的题改成问到本项目（或删掉、或改品牌范围），才能保存和发起诊断。

这条查询只忽略大小写和空格，程序里的判断还会统一全角半角，个别题可能多列出来，以程序提示为准。本机库 2026-11-25 的结果：方案 29 有 3 道、方案 30 有 21 道、方案 31 有 10 道。

## 2. 服务器：改库（整段粘贴执行）

```bash
cd /root/colorful-geo-mgmt/deploy && docker compose -f docker-compose.yaml --env-file .env exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot --default-character-set=utf8mb4 colorful_geo' <<'SQL' && echo QUESTION_PROMPT_MIGRATION_OK
-- 制题提示词写明品牌范围（2026-11-25 用户确认）：两个制题提示词各新增一版。
--   生成母题：写明 NON_BRAND、BRAND、COMPARISON 各指什么；BRAND 是直接询问本项目，COMPARISON 是本项目与竞品比较，
--             两者的问题里都必须出现项目名称或别名；不设计只问竞品、或只比较竞品的问题。
--   按地域改写：品牌名不翻译、不音译、不换成代称；BRAND、COMPARISON 母题改写后必须仍出现项目名称或别名。
--   起因：旧说法只写“品牌认知与竞品比较单独标记”，模型把只问竞品的题标成了 BRAND、COMPARISON，报告里没有可统计的品牌评价，对比胜负还会算错。
-- 做法：取每个提示词的最新一版，把其中的旧句子换成新句子后存为下一版；页面上改过的其他内容原样保留，旧版本不动。
-- 先检查再执行，可重复执行：最新一版里已经没有旧句子时（已执行过，或这几句已在页面上改写过）不新增版本，末尾的核对查询会指出需要人工处理的提示词。
-- 新库直接使用 001_init.sql，无需执行本脚本。只新增行，不改表结构，不动已有的行。
SET NAMES utf8mb4;

-- 1. 生成母题提示词：最新一版同时含有两处旧句子时才新增一版
INSERT INTO geo_prompt_template (prompt_key, version, content)
SELECT latest.prompt_key, latest.version + 1,
       REPLACE(REPLACE(latest.content,
           '品牌认知与竞品比较单独标记。',
           '直接询问本项目、或把本项目与竞品比较的问题单独标记。'),
           '品牌范围仅用 NON_BRAND, BRAND, COMPARISON。竞品比较问题标记 COMPARISON。',
           '品牌范围仅用 NON_BRAND, BRAND, COMPARISON，按问题有没有问到本项目来标记：
- NON_BRAND：不出现项目名称及任何别名的品类或场景问题；不出现品牌名的品类之间的比较也标记 NON_BRAND，意图用 COMPARISON。
- BRAND：直接询问本项目，问题里必须按项目资料里的写法出现项目名称或任一别名。
- COMPARISON：把本项目与竞品放在一起比较，问题里必须按项目资料里的写法出现项目名称或任一别名。
不设计只询问竞品、或只比较竞品而不涉及本项目的问题。')
FROM (SELECT prompt_key, version, content FROM geo_prompt_template
      WHERE prompt_key = 'DIAGNOSIS_PLAN_QUESTION_GENERATE' ORDER BY version DESC LIMIT 1) latest
WHERE INSTR(latest.content, '品牌认知与竞品比较单独标记。') > 0
  AND INSTR(latest.content, '品牌范围仅用 NON_BRAND, BRAND, COMPARISON。竞品比较问题标记 COMPARISON。') > 0;

-- 2. 按地域改写问题提示词：最新一版含有旧的第 4 条时才新增一版
INSERT INTO geo_prompt_template (prompt_key, version, content)
SELECT latest.prompt_key, latest.version + 1,
       REPLACE(latest.content,
           '4. 母题里出现的品牌名保持原样；NON_BRAND 母题改写后不得出现项目名称或任何别名；不添加母题没有的品牌。',
           '4. 母题里出现的品牌名保持原样，不翻译、不音译，也不换成“该品牌”这类代称；BRAND、COMPARISON 母题改写后必须仍然出现母题里的项目名称或别名；NON_BRAND 母题改写后不得出现项目名称或任何别名；不添加母题没有的品牌。')
FROM (SELECT prompt_key, version, content FROM geo_prompt_template
      WHERE prompt_key = 'DIAGNOSIS_PLAN_QUESTION_LOCALIZE' ORDER BY version DESC LIMIT 1) latest
WHERE INSTR(latest.content, '4. 母题里出现的品牌名保持原样；NON_BRAND 母题改写后不得出现项目名称或任何别名；不添加母题没有的品牌。') > 0;

-- 3. 核对：两个提示词的最新一版都应显示“已是新说法”；显示“需人工核对”的，到「基础配置 → 提示词管理」对照 001_init.sql 手工改写后保存
SELECT t.prompt_key AS 提示词, t.version AS 最新版本,
       IF(INSTR(t.content, IF(t.prompt_key = 'DIAGNOSIS_PLAN_QUESTION_GENERATE',
               '不设计只询问竞品、或只比较竞品而不涉及本项目的问题。',
               'BRAND、COMPARISON 母题改写后必须仍然出现母题里的项目名称或别名')) > 0,
          '已是新说法', '需人工核对') AS 状态
FROM geo_prompt_template t
JOIN (SELECT prompt_key, MAX(version) AS version FROM geo_prompt_template
      WHERE prompt_key IN ('DIAGNOSIS_PLAN_QUESTION_GENERATE', 'DIAGNOSIS_PLAN_QUESTION_LOCALIZE') GROUP BY prompt_key) latest
  ON latest.prompt_key = t.prompt_key AND latest.version = t.version
ORDER BY t.prompt_key;
SQL
```

预期：输出两行核对结果，两个提示词都显示「已是新说法」，最后一行 `QUESTION_PROMPT_MIGRATION_OK`。

- 某一行显示「需人工核对」：这个提示词的最新一版里找不到要替换的旧句子（在页面上改写过），脚本没有动它。到「基础配置 → 提示词管理」打开它，对照 `src/main/resources/db/mysql/001_init.sql` 里同名提示词的写法，把品牌范围的定义补进去后保存。
- 没有 `QUESTION_PROMPT_MIGRATION_OK`：把输出发回处理。

脚本的做法是取最新一版、只替换其中的几句旧话、存为下一版，所以页面上改过的其他内容会保留，旧版本都还在。

## 3. 发新代码

- 新代码已上传到服务器：`cd /root/colorful-geo-mgmt/deploy && sh rebuild.sh`
- 还没上传：在本地执行 `sh deploy/upload-code-to-server.sh -r`，上传并在服务器重建

重建完成后看日志：`docker compose -f docker-compose.yaml --env-file .env logs --tail=100 app`，应有 `Started GeoBoot`。

## 4. 验证

1. 打开「基础配置 → 提示词管理」，两个制题提示词的当前版本比执行前多一版，内容里有「不设计只询问竞品、或只比较竞品而不涉及本项目的问题」和「BRAND、COMPARISON 母题改写后必须仍然出现母题里的项目名称或别名」。
2. 方案页新建一个方案，生成候选：品牌认知题、竞品比较题的问题里都出现了项目名称或别名。
3. 手动加一道品牌范围为「品牌认知」、但只问竞品的题，保存：提示「第 N 个问题的品牌范围是品牌认知或竞品比较，但问题里没有出现项目名称或别名，请调整内容或品牌范围」，方案没有被保存。
4. 第 1 步查出的方案：发起诊断任务会得到同样的提示；改好题后能正常保存和发起。
5. 打开一份已完成的报告，点「重新生成报告内容」：① 样本说明里出现「未问到目标的点名、对比题回答」（这份报告有这类题时）；⑦ 的正面证据、负面证据下列出了对应的回答。

失败停止点：第 2 步没有 OK 标记时不发代码；第 3 步启动失败时先看日志，不重复执行改库。

## 回退

- 提示词：在提示词管理页载入上一版内容再保存（新增一版，内容回到旧说法）。脚本新增的行不用删。
- 代码：回退到上一版后，新校验和报告的新统计口径一起消失；已保存的方案、任务和报告不受影响，已重新生成过内容的报告保留新口径的数字，直到再次重新生成。
