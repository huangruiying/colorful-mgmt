# 需求背景

诊断报告新增两个页签：⓪ 诊断大盘、⑦ 地域报告，先做 ⑦。⑦ 按地域（国家或区域，如美国、中国、东南亚、非洲）分子页签，每个子页签回答四件事：

1. 品牌在该地域的宣传状态是正向还是负向，带可查看的证据；
2. 品牌在该地域大模型回答里的可见度；
3. 品牌在该地域的机会；
4. 提升策略和打法：结合本土特点的品牌优化方向，没被正向点名的怎么变成正向点名，已正向点名的怎么提升排名，要有操作路径。

**现有数据做不了地域拆分**（2026-11-15 核对代码与本机库）：问题只有语言字段，没有地域；项目档案的目标市场只是一段文字；被测模型只收到问题原文，联网搜索不带位置。例如 Olight 方案 #28 的 50 道题全是通用英文问题，回答无法归到任何地域。所以先让问题带地域，再做 ⑦。

**核心语义：**

- 一道题只属于一个地域；`region` 为空表示不分地域。
- 地域和语言是两个独立字段：地域决定 ⑦ 里分到哪个子页签，语言决定用什么话问。东南亚可以用英语；新加坡想测英语和中文，就生成两批，都记在新加坡下。
- 覆盖几个地域，就把同一批母题按地域各改写一份，每份各问一次。同一句话不能代表多个地域：被测模型分不出替哪个地区回答。
- 被测模型仍然只收到问题原文，不带项目资料，也不带位置参数。
- 地域在制题时必选（2026-11-16 起）；母题按本次选的地域来出。项目档案的目标市场、目标语言只在页面上展示作参考，不发给模型，也不参与统计。
- 只有诊断执行联网搜索；制题、改写、报告判定与分析都不联网（2026-11-16 起）。
- 报告语言在生成报告时选，默认中文：解析出来的文字按报告语言书写，问题、回答、引用等原文不翻译；页面固定文字和规则拼出的标题保持中文。

**本方案目标：**

- 制题时一次生成多个地域的本地化问题，保存时每道题带地域。
- 报告新增 ⑦，按地域给出四部分内容，结论都能追到回答原文。
- 不迁移历史：旧任务、旧报告照常可用，旧报告的 ⑦ 显示空。

# 实现逻辑

## 整体逻辑

```Plain Text
制题   母题 N 道 ──按行改写──▶ 美国·英语 N 道、德国·德语 N 道、东南亚·英语 N 道 …（共 N × 行数）
保存   每道题带 region（可空）
任务   region 冻结进问题快照；被测模型只收问题原文
报告   ①–⑥ 不变；⑦ 按问题快照里的 region 分组
```

|---|---|
| 数据 | 问题表加 `region`，可空，最多 50 字；去首尾空白，空白视为不分地域 |

| 改写规则 | 意图、品牌范围、核心需求不变，换成当地语言、说法和场景，不是逐字翻译；同语言的地区要能从题目看出是哪里（英国说 torch、美国说 flashlight）；原题里的品牌名保持原样，非品牌题仍不能出现项目名或别名；项目资料里的目标市场、目标语言不发给模型 |

### 第二步：⑦ 地域报告（已完成，待检查）

- 范围：只分析本报告（本次诊断任务）的有效回答，按问题快照里的 region 分组，每个地域一个子页签；不分地域的回答不计入，页面注明条数。
- 旧报告：summary 里没有地域内容，⑦ 显示「本报告没有地域数据」。⑦ 不计入报告缺失内容（不加入 `SUMMARY_PARTS`），旧报告不会因此出现「补全报告」。对旧任务重新生成报告能正常完成，⑦ 仍为空，因为旧任务的问题没有地域。（2026-11-19 起「补全报告」与 `SUMMARY_PARTS` 已删除，报告改为分两段执行，早期报告缺内容时用「重新生成报告内容」，见[验收记录第六步](诊断问题带地域-验收.md)。）
- ⑦ 只出现问题里有的地域；项目目标市场里写了但没出题的地域不会出现。

| 部分 | 内容 | 口径 |
|---|---|---|
| 1 宣传状态 | 结论与正、中、负回答数；正面证据和负面证据（保留意见、负面点、错误描述）逐条附原文和「看回答」；负面回答引用的平台 | 计入的回答：点名题里有情感判定的，加上其他题里提到目标且有推荐强度的。首推、强推算正面，明确不推荐算负面，其余算中性。正面 ≥ 50% 且负面 < 20% 为正向，负面 ≥ 30% 为负向，其余为中性；计入的回答少于 3 条为证据不足。阈值为可调常量 |
| 2 可见度 | 各模型的提及率、推荐率、首推率、平均排名、问题覆盖率、稳定性；目标与预设竞品同口径对比 | 只算该地域的非品牌题，算法沿用 ① 和 ④ |
| 3 机会 | 编号清单（如 R1-O1，全报告唯一），每条附数字和证据；没有数据的类型不出现 | 按顺序：竞品占位（目标从未出现、别的品牌被推荐的题）、空白题（目标没出现、也没有品牌被推荐）、提到未推荐、推荐未首推（排名靠后、并列或附带缺点）、用户在意（没提到目标的回答里的选择标准与顾虑）、口碑改善（针对目标的缺点、点名题负面评价、错误信息，让品牌方向也有证据可引）、渠道空白（常被引用但从未引用到官网或我方发布的平台） |
| 4 提升策略 | 品牌优化方向（结合本土特点）；从未点名到正向点名；已正向点名如何提升排名。每条有操作路径（做什么 → 发到哪 → 用哪些题复测）和证据状态 | 每个有机会的地域用报告冻结的判定渠道调用 1 次模型。两类打法必须引用已知机会编号且有操作步骤；品牌方向没有对应机会时只能是「待验证推测」；未知编号剔除；三类都没有有效条目记为失败。没有机会的地域不调用模型。某个地域失败只影响该地域，报告照常完成 |

- 提示词里的宣传状态只带每个维度排行的前 5 项、每项一句原文：完整排行带多句原文，提示词过长容易超过统一的 60 秒超时（当时判定渠道还会强制联网，第三步起内部调用不再联网；2026-11-16 起统一超时改为 600 秒）。用报告 #12 真实数据实测，一个地域的提示词约 1.1 万字。

### 第三步：地域必选、只有诊断执行联网、报告语言（2026-11-16，已完成，待检查）

起因：用户实测按地域改写时，千问单次要 75～95 秒。查明原因是联网搜索被强制打开：千问、GPT、豆包、DeepSeek 策略对每次请求都带 `tools=[web_search]`、`tool_choice=required`，制题、改写、报告判定等内部任务也要先搜网页。

| 项 | 做法 |
|---|---|
| A 地域必选 | 生成候选至少一行地域，页面打开即有一行空地域；上方「问题语言」改名「母题语言」，默认中文（母题只用于改写和审核对照）。生成母题接口新增 `regions`（必填），母题提示词写明「母题之后会改写到这些地域，要在这些地域都成立，不写具体国家、城市、货币或购买渠道」。两个制题提示词发给模型的项目资料去掉目标市场、目标语言；页面把这两项一起展示，注明仅供参考。手动添加的题和旧方案的题仍可不分地域 |
| B 只有诊断执行联网 | `LLMQueryRequest` 新增 `enableWebSearch`，默认 false；只有诊断执行（`DiagnosisTaskWorker`）和测试接口 `/test/llmQuery` 用 `LLMQueryRequest.withWebSearch` 打开。Responses 父类判断开关，打开才调用子类的 `addWebSearchParams` 挂载厂商搜索参数；子类只负责翻译成自己的参数，不判断用途。流式读取与是否联网无关，照旧开启。千帆智能搜索（接口本身就是搜索）和 `gpt-5-search-api` 这类搜索专用模型不受开关控制，内部任务不要选用。内容优化也随之不再联网 |

# 测试关注点

- 问题地域填空白，是否保存为不分地域。
- 地域超过 50 字，是否拒绝保存并提示。
- 旧方案（问题无地域）编辑后保存，是否不报错且地域仍为空。
- 改写时模型返回的数量与母题不一致，是否整批失败（502）且已有问题和候选保留。
- 改写结果的意图、品牌范围，是否与母题一致。
- 指定语言时，改写题的语言是否都为指定语言；未指定时，是否使用模型给出的语言。
- 非品牌母题改写后出现项目名或别名，是否整批失败。
- 同一地域加两种语言（新加坡英语、中文），是否都记在新加坡下。
- 生成数量 × 行数超过方案剩余容量，是否在调用模型前提示。
- 某个地域改写失败，是否提示失败的地域，已有问题保留。
- 发起任务后，问题快照是否带 region；旧任务（快照无 region）的详情是否显示不分地域。
- 导入旧版导出文件（问题没有 region），是否导入成功且地域为空；导出再导入，地域是否保留。
- 未加列就部署代码，是否出现方案问题查询失败（发版顺序验证）。
- 改写失败时，日志是否有对应渠道的模型调用失败记录，且不含问题原文和凭据。
- ⑦（第二步）：旧报告是否显示空且无补全按钮；单个地域的策略生成失败，是否只影响该地域。
- 没有机会的地域，是否不调用模型、显示"未生成策略"。
- 模型给出的策略全部没有引用已知机会编号，是否记为该地域策略失败。
- 有态度的回答少于 3 条时，宣传状态是否为证据不足。
- 平台上出现过官网或我方发布的内容时，是否不算渠道空白。
- 切换模型筛选或切到别的页签再回来，是否仍停在之前选的地域。
- 导出网页里，⑦ 的地域子页签能否切换，地域机会的「看证据」能否打开。
- 第三步：删掉全部地域行后点生成，是否提示“请至少添加一个地域”且不调用接口；接口不带 regions 或全是空白，是否返回 400 且不调用模型。
- 第三步：母题提示词是否带上去重后的地域、且不含项目目标市场与目标语言；改写提示词是否同样不含这两项。
- 第三步：诊断执行的请求是否带搜索参数；制题、改写、判定、维度归一、建议、地域策略的请求是否都不带 tools、tool_choice。
- 第三步：报告语言留空是否按中文；超过 50 字是否返回 400；旧页面不带请求体是否按中文生成。
- 第三步：选英语时，观点概括、维度名、建议、策略是否为英文，引用片段是否仍为回答原文；补全旧报告是否按中文。
- 第三步：导入报告语言加入前导出的文件，报告语言是否为中文；导出再导入是否保留报告语言。
