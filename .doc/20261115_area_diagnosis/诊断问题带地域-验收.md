## 架构复核

- **分层**：Controller（接收请求、502 映射）→ `DiagnosisPlanBusiness`（Request → Entity → Response 显式转换）→ `QuestionGenerateService`（制题与改写，经 `LLMClient` 调用）→ `GeoDiagnosisPlanService`（问题规则）。没有新增层或中间对象；改写入参复用 `DiagnosisQuestion`，只新增一个 Request。
- **数据**：问题表加一个可空列；任务快照、报告汇总是 JSON，不改表。地域只存在问题上，项目目标市场只作参考，没有两处维护同一事实。
- **事务与幂等**：改写不写库，不涉及；保存沿用原事务。
- **外部调用**：每个改写请求调用 1 次制题模型，页面逐行请求，单次时长受统一 60 秒 HTTP 超时约束；失败不重试、不换渠道，整批返回 502。
- **兼容**：接口字段只增不删；不传 region 视为不分地域；导出文件版本仍为 v1，旧文件缺 region 仍可导入；旧任务快照无 region 显示为不分地域。
- **发布顺序**：先执行 ALTER，再部署代码。实体多了 region，未加列时查询方案问题会失败。

## 架构复核

- **分层**：规则计算留在 `report/summary`，模型调用留在 `report/llm`，编排仍在后台执行器；没有新增层。⑦ 复用 ①③④ 的算法（改为包内可见），不复制口径。
- **数据**：summary 新增 region（JSON），不改表；region 不进 `SUMMARY_PARTS`，旧报告不出现补全按钮（用户确认"历史不用考虑"）。
- **事务与幂等**：策略在冻结前生成，与建议同一次写入；某个地域失败只记在该地域，不重试、不切换渠道。
- **外部调用**：每份报告多 N 次模型调用（N 为有机会的地域数）。提示词里的宣传状态做了精简，控制在统一 60 秒超时内。
- **前端约定**：子页签是链接、渲染不绑定事件，页面与导出各自切换；证据弹窗查找范围扩到地域机会，页面与导出共用。项目约定已同步。

## 架构复核

- **联网开关的位置**：是否联网是调用方的用途，放在请求对象上，由调用方声明；各策略只把它翻译成厂商参数，父类统一判断，子类不判断用途。没有新增层或策略副本，也没有按渠道配置两份（同一渠道既可能被测、也可能出题或判定）。
- **默认值**：默认不联网，新增的模型调用不写就不搜；只有诊断执行与测试接口显式打开，并由单测固定。
- **报告语言的数据**：存在报告表一列，生成时确定、之后不变；判定结果按报告存储，两种语言就是两份报告，不存多份译文。默认中文同时写在表默认值（给旧数据和旧导出文件）和服务常量（给新请求），两处语义一致并在常量注释中说明。
- **兼容**：生成报告接口的请求体可省略；导入时缺少的后加列不写，由数据库默认值补上，不在代码里复制默认值；生成母题接口新增的 `regions` 为必填，是用户确认的行为变化，页面已同步。
- **事务与资源**：报告语言在锁任务前确认，超长时不加锁、不写库；联网开关不涉及连接资源，流式读取方式不变。

## 架构复核

- 沿用第八步的分工：模板读写在 `GeoPromptTemplateService`，填变量用 `PromptTemplateRenderer`。
- 制题、内容优化各自只有一个调用点，取模板和填值留在原服务里，不为它们另建 `*Prompt` 类。
- 取模板放在入参校验之后、调用模型之前：输入不合法时不查库，提示词缺失时不调用模型。
- 同步接口缺提示词直接报错返回页面，不像报告那样暂停；也不冻结版本，每次调用用当前版本，与报告第 2 段一致。
- 异常沿用全局 `NoSuchElementException → 404`，不新增异常类型或控制器处理。
