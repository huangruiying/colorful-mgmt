# 诊断报告表改名 - 服务器执行步骤

直接改库，再重启为新代码（用户确认不必先停服务）。改库命令里直接带 SQL，不用往服务器传文件。SQL 即同目录 [诊断报告表改名.sql](诊断报告表改名.sql)：先自动核对，不满足时报错停止、不做任何修改；再按需补上本分支更早的两次加列（问题地域、报告语言），然后改名。本机库已于 2026-11-18 执行并核对通过。

改库到重启完成之间，旧服务读写报告会报错；后台正在生成的报告保持生成中，新代码启动后续跑。服务器目录按 `deploy/upload-code-to-server.sh` 的 `REMOTE_DIR`（`/root/colorful-geo-mgmt`）书写。

## 1. 服务器：整库备份

备份含业务数据和模型凭据，之后复制到服务器之外保存。

```bash
cd /root/colorful-geo-mgmt/deploy
umask 077
docker compose -f docker-compose.yaml --env-file .env exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysqldump -uroot --single-transaction --no-tablespaces colorful_geo' \
  > /root/colorful_geo-before-report-rename-$(date +%Y%m%d%H%M).sql
```

## 2. 服务器：改库（命令里直接带 SQL）

整段粘贴执行，`<<'SQL'` 与末尾单独一行的 `SQL` 之间是 `诊断报告表改名.sql` 的全文（粘贴时注意不要混入 Tab，终端会把 Tab 当作补全）：

```bash
cd /root/colorful-geo-mgmt/deploy && docker compose -f docker-compose.yaml --env-file .env exec -T mysql \
  sh -c 'MYSQL_PWD="$MYSQL_ROOT_PASSWORD" exec mysql -uroot --default-character-set=utf8mb4 colorful_geo' <<'SQL' && echo RENAME_OK
（这里粘贴 诊断报告表改名.sql 的全文）
SQL
```

预期：只输出 `RENAME_OK`。报 `Table '...前提不满足_可能已改过名或约束名不符_未做任何修改' doesn't exist` 表示核对没通过，库没有任何改动，把输出发回处理。

2026-11-18 已用 bash 按这一写法（容器换成本机、库名换成临时库）对“缺两列、有状态索引、带真实数据”的库执行：输出 `RENAME_OK`，三张表结构与新 `001_init.sql` 一致。

## 3. 重启为新代码

- 新代码已上传到服务器：`cd /root/colorful-geo-mgmt/deploy && sh rebuild.sh`
- 还没上传：在本地执行 `sh deploy/upload-code-to-server.sh -r`，上传并在服务器重建

重建完成后看日志：`docker compose -f docker-compose.yaml --env-file .env logs --tail=100 app`，应有 `Started GeoBoot`，没有 `Table ... doesn't exist`。
